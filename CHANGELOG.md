# Changelog

## 1.1.12 — 2026-11-19
- **The vault now works with APIs, not just website sign-ins.** A person saves any API token in their secure vault — GitHub is the example: they create a personal token on GitHub, paste it into their vault once, and the assistant can then work with their own repositories (list them, search, and more) through api.github.com. New tool vault_api: the server attaches the saved secret to the call as the Authorization header; the assistant itself never sees the secret, one person's entry can never be used by another, and if a service echoes the secret back it is scrubbed from the answer. Username+password entries can be used with basic auth. No admin setup and no app registration is involved — it is the person's own key for their own account, which is how token-style services (GitHub and most APIs) are meant to work.

## 1.1.11 — 2026-11-19
- **Incoming voice notes, pictures, videos and files now work.** Until now a message that was only media was skipped in silence. The driver now spots media in an incoming message, downloads the actual file from the Messages page (the element's own address first; clicking for the viewer's download as a fallback), and the assistant receives it on the person's turn: Gemini hears a voice note and sees a picture directly, and a model that can't open that kind of file says so instead of guessing. From there everything works as if the person had typed — search, reminders, notes, scheduling.
- If a file can't be fetched from the page, the person is told plainly ("I could not open it — please type it or send it again") instead of hearing nothing.
- History shows what arrived ([Voice note], [Photo], [Video], [File]) and a caption rides along with its picture.

## 1.1.10 — 2026-11-19
- **Files by text.** When someone asks for a file that lives on the web — a PDF, a form, a document, a spreadsheet, a zip — the assistant now downloads it and sends the file itself as an attachment (up to 100 MB), never a link. A web page address is refused with an explanation, so a page is never texted as if it were a file.
- **Answers jump the queue.** A plain-text answer now goes out before a picture or file send in the Messages queue. A picture that keeps failing used to sit on the shared Messages page while people's questions waited behind it — the assistant looked deaf. Now they get their answer, and the file keeps trying after.
- **The YouTube preview checks its match.** Search results are reordered so a title whose words match the request in order wins, and when the best match's title does not match the words asked for in order (the classic trap: asking for one person and finding another with the same name reversed), the assistant must say it may not be the right one and offer the other matches by number, instead of presenting a wrong guess as the answer.

## 1.1.9 — 2026-11-19
- **No more Bad Gateway when the server restarts or updates.** The dashboard port used to open only after everything had started — including launching the browser for Google Messages, which takes a while and can hang. Until then the site showed Bad Gateway; if the launch hung, it showed it forever while the program was actually running. The port now opens first: while the rest starts, the health check answers and the dashboard page loads, and data calls get a clean "starting" answer they can retry. The browser still comes up in the background exactly as before.

## 1.1.8 — 2026-11-18
- **The Google connect switch actually saves now.** Flipping "Google connect is available to people" showed a green "on" — and stored nothing, so the next visit it was back where it started. The switch was sending its save in a shape the server silently ignored. The server now accepts both shapes, the switch saves the moment it is flipped, and the same silent bug is fixed in the "People may use their own AI keys" switch, which had it too.
- **The admin Google card explains itself.** The switch now sits at the top of the card, and the Client ID / secret are labeled for what they are — the app's one-time Google key, not an account: the admin connects nothing here; each person connects their own Google account on their own page.

## 1.1.7 — 2026-11-18
- **Never silence.** When a picture or voice note could not be sent, the person who asked for it heard nothing — it looked exactly like being ignored (only the dashboard was told). Now a file gets 3 tries, and if it still cannot go through, the person gets a plain text saying so and inviting them to ask again. At most one such note per person per 10 minutes.
- **One attach attempt is capped at about 90 seconds.** The Messages page is shared by everyone; a hopeless attach could sit on it for minutes, holding up other people's texts and new messages behind it. Now it gives up, names the step that failed, and frees the page.

## 1.1.6 — 2026-11-18
- **Pictures and voice notes now go out every way the page allows.** On the real Messages page the file could silently never reach the compose box, so the picture simply never arrived. Attaching was rebuilt: the sender now tries, in order, the attach button's file picker (including its menu), the Ctrl+K / Ctrl+Shift+A shortcut's picker, the hidden file box, and pasting — then dropping — the file itself into the compose box, and it **checks the file's preview is showing before pressing Send**. If a way fails, the next is tried. And when nothing works, the failure now names each step that was tried, so the Activity log says exactly what the page did instead of a silent nothing. Proven in a real browser against pages that allow only one route each (picker only, paste only, file box only).

## 1.1.5 — 2026-11-18
- **Pictures arrive as pictures, never as a link.** The YouTube preview thumbnail was texted as a bare link (…/thumbnail.jpg) when the Messages page would not take the file — the same fallback 1.1.4 removed for audio still existed for pictures. It is gone for everything: a file is sent as the file, or the send fails and is retried. Attaching also got more careful: the driver now checks the file is really staged (its preview shows in the compose box) before pressing Send, using the attach button's file chooser when the hidden file box stages nothing.
- **Video → YouTube, song → YouTube Music.** That is now the standing rule for youtube_audio (search words and the assistant alike), unless the person says otherwise or pastes a link.
- **Google Save says what is missing.** Saving only a Client ID used to answer "Saved." while nothing turned on — it read as "it doesn't work". Now Save refuses politely until both the ID and the secret are in (or a secret is already saved), confirms "Google connect is ON ✓" when it is, and rejects the empty box's example text (1234-abc…) so it can't be saved by mistake.

## 1.1.4 — 2026-11-18
- **Corrected: "your own keys" means your own AI keys (the brain).** 1.1.3 put own keys in the wrong place (Google client keys — that is removed). Now the switch is where it belongs: dashboard → AI keys → **"People may use their own AI keys"** (on by default). Each person adds their own key (Gemini, Groq, OpenRouter…) on their page under **Your AI keys**, and the assistant answers *them* with *their* keys first; the system keys stay as the backup. **Google** is unchanged in spirit: every person connects **their own Google account**, and it is simply an option — a new admin switch (Settings → Connect accounts) turns Google connect off entirely.
- **A secure vault for any account.** On their page, each person now has a **Secure vault**: save a website login, an API token (Cloudflare, anything) or any secret. Secrets are stored sealed and are **never shown again** — not on the page, not in a chat. The assistant can use a saved login to **sign in and do tasks** (the password is filled in by the server; the assistant never sees it), and can see the vault's labels only.
- **Reactions, like a human.** When a message asks the assistant to do something, it now reacts to that very message with the emoji that fits — 🔍 for "look something up", 🎵 for a song, ⏰ for a reminder, ❤️ for thanks, 👍 for a plain job — before the answer arrives. Plain chat gets no reaction. Admin switch: Settings → Reactions.
- **YouTube: confirm first, then the audio.** Asking for a song or video (YouTube or YouTube Music) now first sends the **thumbnail** with the title, who it's by, the **release date** and the **length**, and asks "is this the one?" Only after the person says yes does the audio go out (in full, as voice-note parts, as before). If it's the wrong one, they can pick another match by number.
- **Audio is never a link.** When an audio file could not be attached, the sender used to fall back to texting its link — useless for people without internet, and how "the audio" arrived as links. Audio now only ever goes as the file itself; the attach waits now scale with file size so bigger voice notes get the time they need, and if sending truly fails the person gets a plain failure message, never a link.

## 1.1.3 — 2026-11-18
- **YouTube Music + full-length voice notes.** youtube_audio now also searches **YouTube Music** (source "music", or a music.youtube.com link). Audio is sent in **clear, high quality** and **in full**: the 60-minute cap is gone — anything longer than one voice note (about 15 minutes) is split and sent as **several parts, one after another** (part 1, part 2, …), up to about 6 hours.
- **Connect accounts: your own keys or the system's.** Connect was a dead end whenever the admin had not set up the system Google client ("Google connect is not set up yet"). Now each person can paste **their own** Google Client ID + secret (their own free Google Cloud project) on their page and connect with those; their connections and token refreshes run on their keys, and removing the keys disconnects them. An **admin toggle** (Settings → Connect accounts, on by default) turns own keys off, leaving only the system keys. The person's page shows which keys they are using and walks them through getting their own.

## 1.1.2 — 2026-11-18
- **YouTube by text, as a voice note.** The people using this assistant have no internet, so a YouTube link is worthless to them. Now, when someone asks for a video, song, shiur or lecture ("go to YouTube and find…"), the assistant searches YouTube itself, downloads the best match with **yt-dlp**, extracts the audio, and sends the **audio file itself** in the chat — attached to the reply like a voice note they can play. New tool **youtube_audio** (search words or a YouTube link; up to about 60 minutes); **extract_audio** accepts YouTube links too. The installer and Update now install yt-dlp and keep it fresh (older than 30 days is refreshed, since YouTube changes often); Node, which the app already runs on, is yt-dlp's JavaScript runtime. If YouTube refuses a download from the server's address, the person is told plainly instead of getting a link.

## 1.1.1 — 2026-11-18
- **News and search work again.** Web search only scraped DuckDuckGo's html page, which now answers servers with a bot-check page and zero results — so "latest news" came back "I can't pull that". Search now tries DuckDuckGo html → DuckDuckGo lite → Bing and uses the first that answers, and a new **latest_news** tool reads Google News (RSS, free, no key): top stories or a topic, with headline, source, time and summary.
- **No links for people without internet.** Most people using the assistant by text have no internet, so a link in a text is useless to them. Answers now come in full in the text itself (for news: the headlines and what happened), and links are stripped from replies — they are sent only when the person asks for one ("send me the link", "where can I see that?"). A published site's link still goes with its publish question, as before.
- **Media work: extract audio from a video.** New tools **extract_audio** (a direct video/audio file link → the audio file itself, attached to the reply by text: mp3, m4a or ogg) and **media_info** (length, size, tracks). They use ffmpeg on the server; the installer and Update now install it when missing, and the tool says so plainly when it is not there.
- **Connect accounts: the dead ends are fixed.** The Google connect link lived 15 minutes — Google's consent and "unverified app" screens often take longer, so connecting "didn't work"; it now lives an hour. A connect where Google returns no email no longer saves a broken empty account that made the *next* connect crash. The person's page only shows the Connect button when connect is really ready, and the dashboard Home now warns the admin when Connect accounts was never set up in Settings.
- **People opens on All.** Dashboard → People now shows **All** first (it opened on Waiting); Waiting / Approved / Blocked are still one tap away.

## 1.1.0 — 2026-11-18

## 1.0.9 — 2026-11-18
- **Texts that arrive while the server or the phone is away are answered.** The app remembers when it last had a working chat list. After a restart it answers the chats that got a text since then (before, they were dropped as "old history"). Anything older than 3 days is still left alone.
- **It heals itself when the phone is "not reachable".** After 90 seconds it reloads the Messages page; after 6 minutes it restarts the browser (at most every 15 minutes). Before, it waited, and one outage lasted about 50 hours.
- **Faster to take the session back and to recover.** "Use here" is tried every minute (was 5 minutes); an unreadable page is reloaded after 1 minute (was 3).
- **A failed text is not given up in seconds.** Tries are spaced 10 s, 30 s, 2, 5 and 10 minutes apart, and an ordinary reply gets 6 tries (sign-in codes and admin texts still 3).
- **No chat is forgotten when many change at once.** More than 5 changed chats: the rest are read on the next look.
- **A reboot just works.** The service waits up to 60 seconds for the internet before it starts, and systemd never stops restarting it. (Update now rewrites the service file.)

- Sending: shorter pause between the parts of a long reply (250 ms, was 700 ms) and a faster look for the sent bubble.
- **New look, on phone and desktop** (the redesign): New look, on phone and desktop. The whole web side is redesigned in the colours of the logo: the admin sign-in, the dashboard (Home, People, Connect, Sites, AI keys, Settings) and the person's own web chat at `/me`. Phone: a clean sign-in card under the logo, big buttons and fields (no zooming in, no sideways scrolling from 360 px up), a bottom bar with clear icons. Sign-in for people: the web chat's sign-in now says "We text a 6-digit code to your phone". When the web chat is on, the admin sign-in page shows a link for people who came to chat: "Using the assistant? Open your chat →".
- The person's page on a computer: your name and the menu on the left, the chat in a wide, readable column (not a stretched phone screen).

## 1.0.3 — 2026-11-08
- **Updates: "Checking…" always finishes.** Settings → Updates now ends every check within about 15 seconds with one of three answers: "Up to date (1.0.3)", "1.0.x available — Update now", or "Couldn't reach the update source" with a short reason (no answer in time, no version.json there, broken version.json, address not found). Before, the line stayed on "Checking…" whenever the check or another part of the Settings page failed or was slow, and "Check again" showed no progress.

- **Logo no longer fills the page.** On a phone, 1.0.2 could show the old logo full width above Updates: the page was new but the phone kept the old style and logo files. Now every page asks for its files with `?v=<version>` (style, script, logo, icons, manifest), pages are never cached, each logo has its own small size (28 px in the header, 72 px on sign-in) even if the style file fails, and the dashboard reloads itself once after an update. App icon, favicon and home-screen icons are the new logo everywhere.

## 1.0.1 — 2026-11-05
- **Startup fix:** the service now starts through `/opt/messageassistant/current` (1.0.0 compared plain paths, so through the
  `current` link it never started and restarted in a loop). It now compares real paths.
- **Update from the dashboard:** Settings → Updates → **Update now** (or `sudo messageassistant update`). Nothing updates by itself. It installs only a newer version
  (sha256-checked, never a downgrade): database backup → `releases/<version>` → switch `current` → restart → `/healthz`.
  If the new version does not answer, it goes back to the previous release by itself. Logs: `sudo messageassistant logs`.
- **Dashboard:** Settings → Updates: this server's version and the latest, **Update now** and **Check again**.
- **Installer/updater repair the service file:** `ExecStart` always points at `current/src/server.js` (a hand-edited
  `releases/<version>` path is fixed).
- **Your settings are kept:** an update never changes `/etc/messageassistant/env`, the Caddy files or your data.
  Running the installer again keeps `MSA_HOST`, `MSA_PUBLIC_URL`, `MSA_PORT` and any other lines you added.
- New command: `sudo messageassistant version`.
